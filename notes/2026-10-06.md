# 2026-10-06

## Wine helper processes crashing with SIGSYS under Proton

### Symptom

`coredumpctl` shows repeated `SIGSYS` (`si_code: SYS_SECCOMP`) crashes of `wine64-preloader`
on netrunner, going back to at least May 2026. They show up across GE-Proton, several
proton-cachyos 10/11 builds, and Valve's Proton Hotfix. The process that dies is always a
Wine helper (`plugplay.exe`, `services`, `explorer`, `rundll32`, `xalia.exe`, ...), and it
always dies at `_start+0x26`, which is the preloader's very first syscall.

In every crash the preloader was loaded just below `0x7000_0000_0000`
(e.g. `0x00006ffeac054026`).

### Cause

- NixOS ships `/etc/sysctl.d/55-nixos-aslr-entropy.conf`
  (from `nixos/modules/config/sysctl.nix`), which sets `vm.mmap_rnd_bits` to the kernel's
  `CONFIG_ARCH_MMAP_RND_BITS_MAX`. That is 32 on this kernel; the kernel default is 28.
  This is unconditional and has no NixOS option to turn it off.
- 32 bits of mmap randomization lets the mmap base shift down by up to 16 TiB, so
  binaries sometimes load below `0x7000_0000_0000`.
- Proton installs a seccomp filter to catch Windows code making Linux syscalls directly.
  As far as I recall, it decides by instruction pointer: syscalls from addresses below
  roughly `0x7000…` count as Windows code and get trapped with `SIGSYS`.
- Seccomp filters carry over to child processes. A helper whose preloader landed in the
  low range gets trapped on its first syscall, and since it has no `SIGSYS` handler set up
  yet, the kernel kills it.

It only happens some of the time because it depends on where randomization places the
binary.

### Fix (not applied)

Add to `modules/hosts/netrunner/configuration.nix` (and the thinkpad config if gaming
there too):

```nix
# nixos sets mmap_rnd_bits to the kernel max (32), which can push mmap base below
# 0x700000000000. proton's inherited seccomp filter then SIGSYS-kills wine helper
# processes (plugplay, xalia, services) at the preloader's first syscall.
# 28 is the kernel default.
boot.kernel.sysctl."vm.mmap_rnd_bits" = 28;
```

This works because `boot.kernel.sysctl` is written to `/etc/sysctl.d/60-nixos.conf`,
which loads after the `55-` file and overrides it. Verified with:

```sh
nix eval .#nixosConfigurations.netrunner.config.environment.etc.\"sysctl.d/60-nixos.conf\".text
# contains vm.mmap_rnd_bits=28
```

Apply with `sudo nixos-rebuild switch --flake .#netrunner` (no reboot needed), then check
`cat /proc/sys/vm/mmap_rnd_bits` prints `28`.

Trade-off: slightly less ASLR entropy, back to the kernel default.

### Impact if left alone

Losing `xalia` (Proton's accessibility helper) doesn't matter. Losing `plugplay` or
`services` can sometimes cause controller or device detection problems, or a game hanging
on launch or exit.
